# 1.2 · 这次，我想怎么上班

## 玩家流程

首页领取工牌 → 选择特质和年度目标 → 选择四周计划 → 每周事件与反馈 → 查看职场手记 → 下一周期 → 年度档案和人生收藏。

开始新人生时，已有进行中存档先确认；进入工牌页尚不覆盖存档，点击「开始这一年」才替换。收藏使用独立存储键，不受重新开局影响。

## 特质和目标

| 特质 | 规则 | 专属选择示例 |
| --- | --- | --- |
| 擅长沟通 | 每次正向关系变化额外 +1，信任最多 10 | 会议中分别确认诉求 |
| 技术专精 | 事件直接经验收益 ≥5 时，额外经验 +2 | 线上故障写诊断脚本；演示前自动检查 |
| 边界清晰 | 事件直接精神损耗减少 2，最多减至 0 | 需求变更时按约定拆分交付 |

年度目标在完成第 52 周后判断：自由基金要求存款 ≥30,000；第一次带队要求项目组长或以上；把生活过好要求健康和精神均 ≥70。目标可在手记查看进度。提前结束不授予年度目标完成记录。

## 四周计划

| 安排 | 立即支出 | 第四周效果 |
| --- | --- | --- |
| 进修技能 | 400 | 经验 +10，精神 −3 |
| 经营关系 | 200 | 三位人物信任各 +2，精神 +4；沟通特质对各人再 +1 |
| 留时间给生活 | 0 | 健康 +8，精神 +8，存款 −200 |
| 寻找新机会 | 0 | 精神 −4，求职准备 +1（最多保留 4） |

每 4 周为一个游戏结算周期，一年共 13 个周期。计划不推进周数，不能重复选择，立即费用不能超过现有存款。第四周先计算事件与计划效果，再结算工资、生活费和晋升。发薪预测计入已安排的休息支出；不预测未来事件收益。

在周期开始、尚未选择计划时，有 2 点求职准备的在职角色可以主动约猎头。这会消耗 2 点准备并替换当周事件；同一周不会重复扣除。待业和已触发裁员时不可使用。联系之后仍需选择本期计划。被替换的剧情没有标为已完成，之后仍有机会触发。

## 人脉与内容

小林、周姐、陈主管的初始信任均为 2，范围 0–10。常规事件和原有剧情也会改变信任；这与「老板好感」是两个独立数值。人脉属于职业生涯中的联系人，换工作不会抹除。

- 信任 6：小林可以代班或协作，周姐可以合作做工具，陈主管可以协助复盘。使用这些协助时的实际关系变化由选项决定。
- 新人物剧情：周姐分享会（第 14 周起、信任 5），主管跨组任务（第 24 周起、信任 6），小林开始带新人（第 36 周起、信任 6）。均只出现一次。
- 总内容：37 个事件定义、8 个条件选项。每张事件卡最多 4 个选项。
- 手记保留最近 80 条记录，每页 4 条，可翻页查看安排、人物剧情、特殊选择和结算信息。

## 存档与收藏

沿用 `office-life-save-v1`，为旧档增加 `life` 字段并保存迁移结果。旧档角色没有新增特质，保留原有数值和剧情标志；新一局可选择特质。

跨局收藏使用 `office-life-collection-v1`。年度结束时记录称号和目标，保留最近 200 个结局运行 ID 用于重复写入去重。旧年度存档迁移使用稳定 ID，即使迁移写入失败，反复加载也不会重复计数。存储失败时显示提示，后续保存/返回首页可重试。

6 个称号沿用现有的优先级，每局授予其中一个。提前结束不增加年度完成次数或称号，但可以重新开始。

## 为后续付费内容保留的边界

`src/content/catalog.js` 将事件、特殊事件和剧情按内容包组织。目前唯一注册的内容包是 `base` / 第一张工牌，全部随游戏提供。条件选项和效果仍由规则引擎处理，内容文件不执行购买逻辑。

下一步可以开发独立公司章节、人物长线剧情和不同职业路线，再确定购买入口与权益模型。目前没有商品、真实交易、解锁凭证或付费墙，也没有把本地收藏当作购买凭据。接入支付时需另行实现平台订单、服务端权益验证和恢复购买流程。

## 本轮验证

- `npm test`：40 项通过；其中包括 100 局基础模拟、300 局新玩法模拟。
- `npm run build`：18 个模块，无第三方依赖。
- 模拟平台交互覆盖工牌配置、计划、事件、手记、确认重开后取消、继续存档。
- 自适应检查覆盖 14 种窗口（280–1440px 宽），验证文字换行、点击区域、滚动可达性和底部固定按钮；另验证 6 种微信胶囊与状态栏组合。
- 电脑控制工具无法取得浏览器画面，实际视觉与触控仍需验收；尚未完成微信开发者工具/真机检查。

真机重点检查：工牌说明与按钮字号、四选项事件卡、月结多条反馈、小屏手记翻页、微信胶囊避让、切后台保存、52 周结束与重复打开收藏。

## 多机型与顶部导航优化

- 移除固定设计高度的整页缩放；正文按实测文字自动增加高度，长内容滑动查看。
- LOGO 和版本号优先放在微信胶囊同一行的左侧；所有页面保留版本号。手记/首页自动计算可用宽度，窄屏收起品牌名称，必要时分行。
- 顶部导航和底部主要操作不参与正文滚动。滑动阈值、多点触控与取消处理用于避免误选选项。
- 微信考虑上下左右安全边距；浏览器读取 CSS 安全区和可视窗口高度，支持窗口变化重新排布。
- 说明文字最小 12px，按钮有效触摸区至少 44px。平板限制内容列宽，高分屏最多 3 倍画布像素。
- 40 项测试全部通过，浏览器产物已重新生成。真实字体和微信触控仍需真机验收。
