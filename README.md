# 我的工牌有想法

1.2.0「这次，我想怎么上班」开发版。一个可运行的微信小游戏单机版本。用随机职场事件推进 52 周人生，围绕存款、健康、精神、老板好感和职业成长做选择。

## 已实现

- 首页、开始游戏、继续存档、返回首页、重新开始确认。
- 存款、健康、精神状态、老板好感、经验、职位和月薪面板。
- 24 条常规事件 + 2 条职业特殊事件 + 11 个剧情节点，共 37 个事件定义；另有 8 个条件解锁选项，每个事件最多展示 4 个选择。剧情分支互斥，并非每局都会遇到全部内容。
- 3 种开局特质、3 个年度目标、4 种月度主动安排。
- 小林、周姐、陈主管的人脉关系、条件协作和职场手记。
- 6 种年度称号与 3 个目标的跨局收藏，重新开始保留收藏。
- 选择结果说明、实际属性变化、工资与生活费结算、职业变化反馈。
- 5 级职业晋升，跳槽加薪、内部转岗、裁员补偿、待业及再就业。
- 健康耗尽、精神耗尽、存款不足和完成 52 周四种结束条件；年度档案和重新开始。
- 自动本地存档、损坏存档降级、快速重复点击保护、高分屏与安全区域适配。
- 同一套游戏逻辑与 Canvas 界面，运行于微信小游戏和浏览器。

## 怎么运行

### 本次升级

1.2 将原有的每周随机事件扩展成「专属工牌 → 四周计划 → 事件与关系 → 年度收藏」：

- **工牌**：擅长沟通增加正向信任收益；技术专精为高经验事件增加经验；边界清晰减轻事件精神损耗。部分特质可直接解锁新选项。
- **计划**：每四周开始选择进修、经营关系、留时间给生活或寻找新机会。费用立即支付，收益在第四周兑现，提前结束不补发。
- **主动跳槽**：两次「寻找新机会」安排完成后，可在之后的计划页联系猎头，替换当周事件。裁员与待业期间不能绕过状态事件。
- **关系**：信任范围 0–10，初始为 2。达到条件后解锁协作和人物剧情；部分求助会消耗信任。人脉随职业生涯保留，跳槽不清零。
- **收藏**：年度称号与成功达成的目标独立保存，每局只记一次。提前结束不计作完成年度。
- **旧存档**：原有进度、数值、剧情继续保留，补齐人脉和手记字段；旧角色不强行追加特质。下一个四周周期可选择计划。

详见 [1.2 版本说明](docs/v1.2.md)。

### 浏览器试玩（最快）

需要 Node.js 18 或更高版本，无第三方依赖，不需要执行 npm install。

在本项目目录打开终端，运行：

```sh
npm start
```

然后打开 <http://localhost:4173>。按 Ctrl+C 停止服务。端口占用时可用 `PORT=4174 npm start`，打开对应端口即可。

`npm start` 会重新生成浏览器打包文件。修改源代码后，重新运行并刷新网页。只生成文件可运行 `npm run build`。

交付内容已包含生成的 `web/bundle.js`，也可以直接打开 `web/index.html` 进行离线试玩；个别浏览器限制本地文件存储时，存档可能不可用，推荐使用本地服务。

### 微信小游戏

1. 在微信开发者工具中导入本项目文件夹 `office-life`（包含 `game.js`、`game.json`、`project.config.json` 的目录）。项目类型为小游戏。
2. 确认 `project.config.json` 中的 `appid` 属于你自己的**微信小游戏**。当前已保留你在开发者工具中填写的 AppID 和配置，其他账号使用时请替换。
3. 编译项目。入口 `game.js` 创建上屏 Canvas 并启动游戏，不需要 npm 构建，也不需要后端、云开发或联网授权。
4. 使用自己的 AppID 后，再通过开发者工具预览到手机，检查屏幕安全区、触摸和切后台存档。

微信入口采用 CommonJS 模块和原生 Canvas。浏览器入口单独打包，浏览器专用 DOM 代码不会从微信入口加载。项目目录与配置参考[微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。

**1.2 验证边界：**已通过自动化逻辑、模拟平台交互、14 种窗口尺寸的文字布局、滚动和点击区域检查和浏览器构建。电脑控制工具未能取得浏览器画面，本轮未完成实际视觉试玩，也未在微信开发者工具或微信真机中实测。未上传、审核或发布。

## 基础规则（1.2 沿用）

| 规则 | 当前实现 |
| --- | --- |
| 开局 | 存款 3000，健康 80，精神 80，好感 50，经验 0 |
| 时间 | 选择一次完成一周；先看反馈，再进入下一周 |
| 收支 | 每个在岗周累计当时月薪的四分之一；每四周发累计工资、扣生活费 3200 |
| 初始月薪 | 4500 |
| 晋升 | 每四周评估一次；在职、好感至少 55、经验达到下一级要求；一次升一级，好感扣 8 |
| 职级 | 初级职员 → 骨干员工 → 项目组长 → 部门主管 → 职场合伙人 |
| 经验门槛 | 0 / 24 / 60 / 104 / 156，晋升后不清零 |
| 基础月薪 | 4500 / 6500 / 9000 / 13000 / 18000 |
| 跳槽 | 猎头事件经验 12 起可出现；接受后月薪补贴 +800，好感重置 45 |
| 裁员 | 下周抽事件时好感 ≤15，或第 12、28、44 周好感 <50 时触发 |
| 失业 | 可领 5000 游戏补偿金离职，或内部转岗；待业时不累计新工资，下周进入求职事件 |
| 再就业 | 保留职级，清零跳槽补贴，好感重置 45；入职后的下一周开始累计新工资 |
| 去重 | 常规事件避开最近 6 条；裁员、求职等状态事件不受去重限制 |
| 数值范围 | 健康、精神、好感为 0–100；反馈显示裁切、职业流转和月结后的实际变化 |
| 结束 | 健康或精神到 0，存款低于 0，或完成第 52 周；若同时满足，先判健康、精神、存款，再判年度完成 |

本作的补偿金与工资为游戏数值设定。当前平衡偏向轻松体验，还需要真实玩家反馈来调整事件收益和难度。

## 新增事件

在 `src/data/events.js` 的 `events` 数组中增加一项：

```js
{
  id: 'unique-event-id',
  tag: '办公室日常',
  title: '一个简短的事件标题',
  text: '描述场景，让玩家明确自己正在做什么决定。',
  minXp: 12, // 可选，经验达到后加入抽取池
  choices: [
    choice('选择一', { mood: 6, money: -100 }, '这一选择的后续结果。'),
    choice('选择二', { favor: 4, xp: 3 }, '另一个结果。')
  ]
}
```

效果字段仅允许 `money`、`health`、`mood`、`favor`、`xp`。职业流转使用已定义的 `action`：`switchJob`、`loseJob`、`transfer`、`hire`，不要把业务逻辑写进界面层。

当前卡片适合标题约 15 个汉字、描述约 45 个汉字、选项约 18 个汉字。加入更长内容时，需要增加滚动或动态卡片高度，并检查小屏显示。

## 扩展方向

- **广告：**在 `services` 新增激励广告服务，由微信适配层封装平台 API，仅在广告完成回调后给予奖励。当前没有广告位、广告请求或模拟收费按钮。
- **排行榜：**先定义年度评价与得分规则；若接全局排名，提交服务端核验的结果，本地存档不能作为可信分数来源。
- **每日事件：**引擎已经支持注入随机数函数。增加固定日期种子和内容版本，让同一天的挑战可复现；单独保存每日挑战进度。
- **AI 事件：**在服务端生成候选内容，经事件结构校验、数值范围限制和内容审核后进入事件库；客户端不持有模型密钥、不执行 AI 生成的代码。当前不会调用模型或产生 API 费用。

## 多机型布局

页面按可用宽度和实际文字高度排布，正文可上下滑动，不再把整页压缩进固定的 390×820 画布。正文默认 14px、说明至少 12px，按钮有效触摸区域至少 44×44px；主要操作固定在底部安全区上方。平板与桌面内容列最多 560px，高分屏渲染倍率最多 3 倍。

微信端读取胶囊的实际矩形，在胶囊左侧放置 LOGO、版本号和导航。空间不足先收起品牌文字，再将导航移至下一行；胶囊信息不可用时回退到预留安全区域。浏览器支持触屏滑动、滚轮、方向键、PageUp/PageDown，并随窗口和可视区域变化重新排布。

自动化覆盖 280–1440px 宽度的 14 种窗口，以及 6 种微信胶囊/状态栏组合。检查使用模拟字体度量和 Canvas 绘制替身，仍需在微信真机确认字体、触控与平台返回的安全区。
